# 数据准备、诊断依据与 AI 使用说明

本说明对应 YOLO 诊断助手第二版。程序做证据诊断，AI 做辅助解释。资料完整度不等于准确率，模型置信度也不等于病因概率。

## 1. 哪些材料能增加诊断能力

### 独立评估集 + YOLO 标签 + data.yaml（必需）

- 准备格式：图片、labels/\*.txt、data.yaml
- 能帮助判断：量化分类、漏检、定位和误报；空 TXT 表示已确认背景图。
- 当前程序处理范围：自动读取全部提供的 train/val/test；仅对选择的分组推理

### 当前模型与旧模型（强烈建议）

- 准备格式：.pt 检测权重，类别名称一致
- 能帮助判断：同图同参数逐目标对照；旧模型不作为真值。
- 当前程序处理范围：当前模型必需，对照模型可选

### 两模型各自的原始训练数据版本（强烈建议）

- 准备格式：保留完整图片、标签、划分、文件哈希和版本号
- 能帮助判断：区分新增样本、类别覆盖和版本差异，核实评估是否见过。
- 当前程序处理范围：当前 YAML 的各分组自动审计；权重与数据的对应关系在补充 JSON 填写，仍属用户陈述。第二套数据请单独建任务审计

### 两次训练的原始结果目录（强烈建议）

- 准备格式：results.csv、args.yaml、best.pt/last.pt 及日志
- 能帮助判断：读学习曲线、参数差异，形成过拟合/未收敛的待验证线索。
- 当前程序处理范围：选择训练目录自动读取 results.csv 和 args.yaml；训练日志、优化器状态仅保留供人工复核，不自动解析

### 问题描述、类别含义和标注规范（强烈建议）

- 准备格式：templates/context.json
- 能帮助判断：明确错成什么、业务影响、容量/SKU真值、遮挡框口径。
- 当前程序处理范围：JSON 自动接入报告；其内容标为用户提供，系统不会当成已验证事实

### 现场推理配置与预处理（强烈建议）

- 准备格式：补充 JSON 中 deployment
- 能帮助判断：比对 imgsz/conf/iou/max_det；记录裁剪、缩放、RGB/BGR、FP16/INT8、导出运行时。
- 当前程序处理范围：可比数值自动对照；代码、ONNX/TensorRT 文件和硬件现场输出需要另做复现，当前不执行

### 现场失败图 + 同条件成功图 + 背景负样本（强烈建议）

- 准备格式：加入带标注评估集，CSV 的 known_failure 字段注明
- 能帮助判断：覆盖真正故障场景，避免只看训练同源测试图。
- 当前程序处理范围：图片按评估集处理；没有标签不能量化漏检；失败标记为用户陈述

### 逐图拍摄与复核信息（可选增强）

- 准备格式：templates/scenes.csv：image,batch,scene,lighting,occlusion,view,distance,known_failure,reviewed
- 能帮助判断：按批次、光照、遮挡等分组观察失败率与独立图片数。
- 当前程序处理范围：CSV 自动读取；文件名必须唯一或使用绝对路径；不自动从像素猜遮挡等级

### 单变量对照实验记录与验收目标（可选增强）

- 准备格式：补充 JSON 中 experiments、acceptance
- 能帮助判断：记录只改什么、控制了什么、随机种子、模型/数据哈希、验证集和最终独立测试结果。
- 当前程序处理范围：记录进入报告和 AI 上下文；文本实验声明不会自动确诊因果，需复核原始产物

### 原始视频、相机参数、采集与部署代码（深入排查）

- 准备格式：原始视频/无损帧、曝光/白平衡/焦距、裁剪前后成对图、环境锁文件
- 能帮助判断：排查运动模糊、域差异、预处理和导出精度。
- 当前程序处理范围：本版不直接分析视频/执行代码；先按时间与批次抽帧标注，在 JSON 记录相机/预处理，相关源码供人工或你另行选择的 AI 审核

## 2. 如何组织与提供

1. 先选择当前模型、对照模型、数据 YAML。保持现场实际推理参数。评估集必须有人工确认的标签。
2. 如果保存了训练结果，在“补充证据”选择当前和对照训练目录。目录必须含 results.csv，可附 args.yaml；参数只存在于权重时仍会读取。不要把不对应的训练曲线配给权重。
3. 复制 context.json 模板，填写真实问题、类别规则、现场配置、训练数据版本、验收目标；不知道写 null 或“未知”，不要照抄示例。
4. 复制 scenes.csv 模板，删除示例行。每行对应所选评估组的一张图，image 使用唯一文件名或完整路径。允许只填写部分图片，但漏填图片不进入场景统计。重名、重复行、不存在的图片会报错。
5. 光照/遮挡/角度取值由你定义但要统一，例如 lighting=室内/逆光，occlusion=无/部分/严重。相同批次用相同 batch。known_failure=true 表示你确认是现场失败样本；不要把所有离线错误自动写为现场失败。
6. 现场视频先按时间和采集批次抽帧，保留成功/失败/负样本并人工标注；同一视频的近邻帧不要分到训练和测试两边。
7. 每次运行会将实际补充资料内容、其 SHA-256、模型哈希和推理版本保存在 report.json 中。原始数据不修改。

不要求凑满固定张数。需要覆盖不同独立批次及业务场景；30 张只是检查提示，不构成统计显著性或泛化保证。更多低质量、重复或矛盾的数据可能降低判断质量。

## 3. 算法与结论边界

### 固定阈值错误计数

Ultralytics 8.4.54 ConfusionMatrix：保留 conf > 用户阈值的预测，以 IoU > 匹配阈值按重叠度去重成一对一匹配；类别正确为 TP，错类别同时贡献该真类 FN 与预测类 FP。P=TP/(TP+FP)，R=TP/(TP+FN)。

限制：相对于现有标签成立。此匹配先看几何再看类别，与 AP 的类别约束匹配不同；改变阈值可能改变配对，TP 不保证单调。

### AP 与排序质量

DetectionValidator.\_process_batch + DetMetrics：conf=0.001 保留的预测，在 IoU 0.50:0.05:0.95 下做原生同类匹配，形成 PR 曲线并积分。

限制：mAP 只平均有真值的类别；不是 conf=0.25 的单点正确率，也不能代表没有采样的现场场景。

### 错误类型影响

TIDE @ IoU 0.50：分类、定位、两者兼有、重复、背景、遗漏六类 oracle 修正后的 AP50 变化。

限制：是假设性上限分析，各项不相加；不是重训能获得的收益，更不是训练根因。

### 逐目标回归和候选框

在同一张图、同一真值框上比较两模型是否进入 FN。候选框取当前阈值下最大 IoU，IoU≥0.10 才展示。

限制：候选框只是可视化线索，不是额外匹配，不证明某个低 IoU 框就属于该物品。

### 数据与场景证据

图片 SHA-256 查完全重复；排序后的标签数值摘要查同图异标；尺寸、边缘、用户 CSV 场景分组统计目标数、失败数与独立图片数。

限制：完全重复不等于近重复检测；图片数量不等于独立拍摄批次。亮度和拉普拉斯方差只描述像素，不用统一阈值确诊模糊。

### 病因与建议规则

将混淆计数、未匹配目标、新旧回归、数据审计、配置差异和学习曲线变成有编号的证据，再生成所需补充数据、竞争解释与单变量实验。

限制：规则没有训练成病因分类模型，也没有经过概率校准。本版不输出伪精确的病因置信度；没有受控干预证据时，根因保持未确诊。

## 4. 报告中的四种内容

- **E 编号，已确认的表现/数据问题**：例如给定标签与阈值下发生两次 CA001→CB003；或者 SHA-256 证明不同分组出现同一图片。描述现象和文件事实，不凭此认定训练根因。
- **H 编号，待验证病因**：每项包含支持证据、缺少的材料、其他竞争解释、可执行的验证实验。不会输出未经校准的病因概率。
- **A 编号，修改与训练建议**：包括数据复核、保留原版本、补难例、推理对照和重训步骤，并列出验收方式。它们尚未执行。
- **已确诊根因**：只有受控改变、原始产物对应关系、重复实验与竞争解释复核都得到支持时，才有资格作因果判断。目前程序不自动认证这些条件，因此该栏保持“尚无已确诊根因”。用户 JSON 和 AI 的断言不会越过这一边界。

### 对你的眼镜/面包和水瓶问题

- 可确认的是某些图上在特定尺寸下发生错分类，或者同一目标旧模型匹配成功而新模型失败。
- 还不能直接确认是过拟合、标签错、增强过强或水瓶视觉外观相似。550ml 的容量需容量标签/SKU或你的现场复核支持。
- 先比较同图同参数两模型，再单独改变推理尺寸；复核类别规范和训练覆盖后，决定是否补数据或重训。
- 不能把已用于调参的两张案例称为独立测试集。案例用于回归，独立批次用于最终验收。

## 5. 建议的实验记录

每次记录：实验问题；原模型/新模型哈希；数据版本/划分；唯一改变项；保持不变的参数；随机种子；训练目录；部署预处理；逐类 P/R/FN/FP/AP；推理耗时；失败样本；结论及反例。

优先顺序：

1. 排除数据版本和推理配置对不上的问题。
2. 人工复核错例，另存标签修订版；不要按预测自动覆盖标注。
3. 同模型同图片仅改变 imgsz，再单独改变 conf。验证集调参数，不反复选择测试集最优点。
4. 固定划分、训练设置，单独比较补充数据/一个增强参数/训练时长；资源允许时比较多个随机种子。
5. 用没有参与调参的新批次测试。重点类别改善的同时检查其他类别与误报是否退化；不合格则回退旧模型和旧数据版本。

## 6. DeepSeek 4.1 与自定义 API

在“AI 辅助诊断”点击“填入 DeepSeek 4.1 配置”：

- 完整接口地址：https://api.deepseek.com/chat/completions
- 模型 ID：deepseek-flash（当前官方对应 DeepSeek‑V4.1‑Flash，核验日期 2026-09-15）
- Key：你在界面填写，不要放在 JSON、CSV、Git 或聊天记录中。只在本服务进程内保存，服务重启后需重填。更换服务地址会清除旧 Key。
- 默认输出上限 8192 token。推理模型可能花较长时间；本项目单次连接/读取超时为 90 秒，不自动重试；实际计费和模型限制以提供商为准。

操作流程：保存配置 → 选择完成的报告 → 填写问题 → 可选勾选最多四张报告预览图和用户补充 JSON → 生成发送预览 → 核对地址、文本、图片和历史回答 → 勾选同意并发送。生成预览不调用外部 AI。

默认仅发送报告的结构化指标、E/H/A 证据与建议；不发送权重、训练目录、完整原始标签文件和原始报告。用户补充 JSON 可能包含路径或业务信息，勾选后会原样包含在可见预览中。所选图片为报告 JPEG，可能已缩放；坐标文字使用原图尺寸。

AI 响应以纯文本展示，避免执行 HTML/脚本。回答保存在 data/ai/任务ID，可下载 TXT；重新进入 AI 页面后可选历史回答继续追问。AI 意见不会改写原始指标、标签或模型，也没有执行训练命令的权限。

只实现 Chat Completions 兼容协议；不承诺所有服务商的私有扩展、长时间流式推理或视觉模型均兼容。未配置真实 Key 时只能验证本地预览和请求流程，不能声称已完成真实云端诊断。

## 7. 代码入口和扩展方式

- core/analyzer.py：保持原生评估和报告生成；读取补充资料路径。
- core/diagnosis.py：数据清单、算法说明、证据/假设/建议规则。新增规则必须有证据来源、范围和验证方法。
- core/ai.py：预览内容投影、API 配置、发送、响应解析和意见保存。
- ui/report.html：E/H/A、数据缺口、方法说明、场景统计。
- ui/ai.js：AI 设置、预览、发送、历史与下载。

可继续发展的方向：近重复图片检索；人工标签复核工作流；训练版本自动关联；场景置信区间与统计检验；导出/部署模型逐层对齐；多种输入尺寸的受控批量实验。这些尚未实现，不能从当前报告中推断已完成。
