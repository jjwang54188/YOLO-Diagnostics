选择这次要分析的内容

这里用于记录和校验你的选择；真正的系列仍以 .pt 权重内容为准。目前诊断任务支持目标检测（detect），不支持分类、分割、姿态和 OBB。

你想检查的模型。报告中称为“当前模型”。

两份模型使用同一批图、同样参数比较。对照模型也可能犯错。

配置应包含 names 类别名称，以及 test 或 val 图片路径。图片需要对应的 YOLO 检测标签。

2

设置分析条件

评估最终效果优先 test；调参数使用 val。分组是否独立仍需核实。

GPU 通常更快；显卡不可用时选择 CPU。

图片送入模型时的尺寸。先和实际使用保持一致；640 与 1024 可能产生不同错误。

多有把握的预测才显示出来。降低可能找回目标，也可能增加误报。

进阶设置：匹配框的严格程度

预测框与标注框重合多少才算匹配。0.5 是本项目默认值；它不是去重用的 NMS IoU。

3

补充证据（可选，提供后报告更有针对性）

没有的资料可以留空。内容会记录为用户提供；系统不会把填报说明自动当成确诊依据。

这里不是 JSON。你可以直接写人话；系统会把它作为“用户提供的背景信息”，不会自动当成确诊原因。

逐图场景不是标签文件：它是“每张图片是在什么条件下拍的”备注表，例如批次、光线、角度、遮挡、距离，以及是否为你确认的现场失败图。没有这些信息可以留空，不影响基本诊断。

报告会告诉你什么

  1. 哪一类表现差逐类召回率、精确率、AP 和样本数量。
  2. 哪些图出了问题标注、预测和错误候选框对照。
  3. 属于哪种错误类别混淆、框不完整、漏检和背景误报。
  4. 新模型有什么变化同一个目标的改善或退步。
报告中的原因线索需要证据复核，不会自动修改你的标注或重新训练模型。

常见问题

            

              只有图片，没有标签，可以分析吗？
              

                这一版需要带标签的数据才能计算漏检和正确率。空 TXT
                表示已确认的背景图；缺少 TXT 会报错，不能自动当背景。
              

            

            

              只有图片文件夹，没有 data.yaml？
              

                可以使用 EzYOLO 导出的训练数据配置。标准目录包含
                images/test、labels/test，并在 YAML 中填写 names 和 test
                路径。开发文档提供了示例。
              

            

            

              “未正确检出”就是没有看到吗？
              

                不一定。类别错、框不完整、框重合不够都会造成
                FN。先看候选预测的类别、置信度和 IoU。
              

            

            

              显存不足或 CUDA 不可用怎么办？
              

                先确认选择了正确设备。可换 CPU，或用较低尺寸另跑。程序推理批量为
                1，避免大模型一次装入多张图。
              

            

            

              模型类别不一致或标签有问题怎么办？
              

                查看日志末尾给出的文件和原因。类别名称相同、顺序不同会自动对齐；类别名称缺失或不同需要先人工确认对应关系。
              

            

            

              高分为什么现场还会错？
              

                测试图可能不覆盖现场的光照、角度、尺度或遮挡；也可能与训练图重复。不要用反复调参使用过的图片证明独立泛化。
              

            

          

        

        

          
项目结构：以后想改哪里，就找哪里

          

            

              
                

                  文件 / 文件夹
                  负责什么
                  什么时候改
                

              
              
                

                  main.py
                  启动服务、文件选择、接口
                  新增一个界面需要调用的接口
                

                

                  core/tasks.py
                  后台运行、取消、日志、历史记录
                  调整任务调度或保存内容
                

                

                  core/analyzer.py
                  读数据、模型推理、指标和错误证据
                  增加新的诊断规则或分组统计
                

                

                  ui/index.html
                  页面文字与表单结构
                  修改中文说明或增加输入项
                

                

                  ui/app.js / style.css
                  按钮行为 / 配色布局
                  修改交互或界面样式
                

                

                  ui/report.html
                  分析结果的报告模板
                  增加图表或错误展示
                

                

                  data/
                  配置、任务记录和日志
                  一般不用手改；可备份
                

                

                  reports/
                  每次分析的完整输出
                  查看、备份和分享整个报告文件夹
