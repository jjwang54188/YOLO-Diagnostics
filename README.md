# YOLO 诊断助手

一个给自己使用、也方便继续开发的本地 YOLO 问题分析项目。用图形界面选模型、选数据、设置参数，再查看进度和中文报告，不需要每次手写命令。

它独立于 EzYOLO：EzYOLO 可以继续负责标注、训练，这个项目负责训练后和实际使用中的模型对比、错误复核。界面借鉴“侧边导航 + 操作页面”的组织方式，没有复制 EzYOLO 的代码或修改它的项目。

## 新版：证据诊断与 DeepSeek 4.1

导航新增“数据清单与算法”和“AI 辅助诊断”。最完整的材料清单、处理范围、方法解释和实验建议在 [数据准备与诊断依据](templates/数据准备与诊断依据.md)。下载 [补充资料 JSON](templates/context.json) 和 [逐图场景 CSV](templates/scenes.csv)，修改示例后在新建分析的“补充证据”选择。

- **E 编号**：已确认的表现、数据问题、配置/曲线事实；注明结论范围和图片入口。
- **H 编号**：尚未确诊的原因、竞争解释、所缺材料和验证实验。
- **A 编号**：数据修订、推理对照与重训建议，包含具体步骤和验收条件；没有自动执行。
- **资料覆盖**：已提供、缺失、需人工复核分别标示；不是诊断概率或准确率。
- **AI**：DeepSeek 4.1 预设 / 自定义兼容接口；仅在预览并同意后发送选定文本、可选图片；返回意见单独保存，不升级为确诊。

旧报告保留原始生成时的内容。要看新版完整结构，请新建任务或复用设置重新分析；AI 页面可读取旧报告并从其已有证据生成辅助输入。新报告输出 `action-plan.json`。

## 1. 下载、安装和启动

当前支持在 Linux / Ubuntu 本机运行，需 Python 3.10+、pip 和适合本机的 PyTorch 环境。

```bash
git clone https://github.com/jjwang54188/YOLO-Diagnostics.git
cd YOLO-Diagnostics
bash setup.sh
bash start.sh
```

浏览器访问 <http://127.0.0.1:8880>。启动日志在 `data/server.log`。在终端前台调试可运行 `.venv/bin/python main.py`。

私有仓库需要仓库访问权限才能下载。仓库只包含应用源码、说明和模板，不包含模型权重、图片、标签、历史报告、虚拟环境或 AI 配置。桌面快捷方式不是必需的。

## 2. 第一次分析

1. 准备自己的检测模型 `.pt` 和带人工标签的 YOLO 数据集配置 `data.yaml`。
2. 打开“新建分析”，选择问题模型；有以前表现较好的模型时，也可选择对照模型。
3. 选择数据配置和 test / val 分组，用普通文字描述问题。
4. 先用少量已确认的问题图片运行，确认类别、路径、参数和标注正确后，再分析完整数据。
5. 完成后打开报告，先复核人工标签与两个模型的预测，再阅读结论和建议。

人工标签来自同一份数据集，是两个模型共同使用的参考答案，不属于某个模型。本机案例按钮需要自行配置 `data/demo.json`；新下载的工程不附带开发者的现场案例。

## 3. 分析自己的模型

### 第一步：准备输入

- **问题模型**：需要检查的本地 `.pt` 检测模型。
- **对照模型**：可选，以前效果较好的 `.pt`；没有就留空。
- **数据集配置**：包含类别名称和图片分组路径的 `.yaml` / `.yml`。

可以直接选择 EzYOLO 生成的数据集配置，例如其 `datasets/project_11/data.yaml`。原始模型、数据和标注按只读使用；所有新结果写入本项目的 `reports/`。

标准数据目录示例：

```text
my_dataset/
├── data.yaml
├── images/
│   ├── val/
│   └── test/
└── labels/
    ├── val/
    └── test/
```

`data.yaml` 示例（请替换成自己的路径和类别）：

```yaml
path: /absolute/path/to/my_dataset
val: images/val
test: images/test
names:
  0: CA001
  1: CB003
```

标签每行格式为 `类别ID 中心x 中心y 宽 高`，坐标归一化到 0～1。类别编号必须和这个 YAML 一致；模型和 YAML 的类别**名称集合**也必须一致。两者名称相同、排列顺序不同，可以按名称重映射。示例类别需要替换成自己的完整类别列表。

每张图应有对应 TXT；确认没有目标的图片使用空 TXT。**没有标签的现场图片不能直接用于量化漏检率。**

### 第二步：理解参数

| 环节       | 参数        | 人话解释                 | 什么时候调整                                     |
| ---------- | ----------- | ------------------------ | ------------------------------------------------ |
| 选择数据   | test / val  | 这次检查哪一组图片       | 最终评估用独立 test；调阈值用 val                |
| 推理       | imgsz       | 图片送入模型时的尺寸     | 先用实际识别程序的值，再做单变量尺寸对照         |
| 展示与计数 | conf        | 预测多有把握才算显示出来 | 太低会多误报，太高可能漏掉目标；先和现场保持一致 |
| 匹配       | match IoU   | 预测框要与标注框重合多少 | 要求更精确定位时提高；它不是 NMS 的 IoU          |
| 计算       | GPU 0 / CPU | 用显卡还是处理器运行     | 有可用 NVIDIA 显卡优先 GPU；否则 CPU             |

本项目固定使用 Ultralytics 8.4.54，与之前的诊断报告保持一致。以后升级推理库时，请对两份模型一起重跑；不要直接把不同版本报告之间的数值变化归因于模型。每份报告都保存实际运行版本。

模型实际推理会保留 `conf=0.001` 以上的预测以计算 AP，报告逐框证据使用你填写的 conf。推理批量固定为 1，便于本机 8GB 显存使用 YOLO26x。不会自动重训、修改标注或调参。

### 第三步：读结果

- **精确率 P**：给出的预测有多少正确。
- **召回率 R**：标注目标有多少被正确找到。
- **FP**：多余预测或错类别预测，相对于现有标注统计。
- **FN**：未正确匹配的目标，包括错分类、框不完整和没有检出。
- **AP50–95**：不同定位严格程度下的综合表现，不能仅由显示的 FP/FN 反算。
- **候选框解释**：显示与未匹配目标最重叠的预测，帮助理解类别与框的问题，不改变原生的一对一匹配结果。
- **TIDE 错误影响**：假设修正某类错误后 AP50 能提高多少；不是实际调参收益，各项不能直接相加。

先点开错误图片复核，再决定下一步。对照模型同样可能错；多个模型同意某个预测，也不能自动证明标签错。

## 4. 历史、日志和取消

- 每次运行都会生成唯一任务编号，结果目录不会覆盖旧报告。
- “历史报告”可以按名称、模型和状态筛选，支持打开报告、查看日志、复用配置。
- “取消分析”只停止当前分析进程，已有文件和日志保留，取消任务不会被标成成功。
- 上次服务异常退出的任务，下次启动会显示“已中断”，不会伪装成仍在运行或已经完成。
- 每次只运行一个任务，避免两个大模型分析同时争抢显存。
- 界面使用的进度来自实际处理图片数；模型加载和数据检查阶段不伪造百分比。

## 5. 文件都放在哪里

```text
YOLO-Diagnostics/
├── main.py                 # 启动入口、HTTP 接口、本地文件选择
├── start.sh                # 日常启动
├── setup.sh                # 首次准备 Python 环境
├── requirements.txt        # 诊断依赖版本
├── README.md               # 本说明
├── core/
│   ├── tasks.py            # 任务进程、取消、持久化、日志
│   └── analyzer.py         # 数据审计、推理、指标、错误解释、报告生成
├── ui/
│   ├── index.html          # 四个操作页面的结构和中文文案
│   ├── app.js              # 浏览文件、提交任务、更新进度
│   ├── style.css           # 颜色、尺寸、布局
│   └── report.html         # 分析报告模板
├── data/                   # 自动生成，不提交 Git
│   ├── settings.json       # 上次提交的分析设置
│   ├── demo.json           # 本机演示案例配置（可选）
│   ├── server.log          # 启动脚本的服务日志
│   ├── runtime/            # 隔离的 Ultralytics 配置
│   └── jobs/               # 每个任务的 JSON 状态与 .log 日志
├── reports/                # 每个任务的报告、预览图、预测数据、CSV
├── templates/              # 全部所需数据说明、JSON/CSV 模板
└── .venv/                  # 项目自己的 Python 虚拟环境
```

这整个 `YOLO-Diagnostics` 文件夹就是应用项目，不依赖外面的 Ultralytics 源码检出目录。模型和原始数据是外部输入路径；移动文件夹或换电脑后，请重新选择这些输入。不要在新机器上直接复用 `.venv`，重新安装环境。

旧脚本已移动到 `core/analyzer.py`，不会保留两份不同的诊断实现。以前生成的独立报告仍可打开。

## 6. 后续怎么完善

建议从小改动开始，每次改完用两张复现图片跑一遍。

| 想做什么               | 从哪里改                                             | 如何确认改对了                                     |
| ---------------------- | ---------------------------------------------------- | -------------------------------------------------- |
| 修改中文提示、按钮名称 | `ui/index.html`                                      | 刷新页面查看，点一次相关按钮                       |
| 调整主题与布局         | `ui/style.css`                                       | 检查宽屏和窄屏，确认按钮、表格仍可用               |
| 增加表单参数           | `index.html` + `core/tasks.py` + `core/analyzer.py`  | 表单名、后端校验、命令参数三处保持一致             |
| 增加一种错误证据       | `core/analyzer.py` 的 `explain_misses` 或 `findings` | 用已知真实图片核对框和统计，不把相关性写成确定原因 |
| 增加报告图表           | `ui/report.html`                                     | 先从 `report.json` 确认数据存在，再显示图表        |
| 改进任务管理           | `core/tasks.py`                                      | 检查成功、失败、取消、重启后恢复状态               |

主调用链：**界面表单 → main.py 接口 → tasks.py 启动子进程 → analyzer.py 生成报告 → 界面显示完成**。

继续复用原生 `DetectionValidator`、`DetMetrics`、`ConfusionMatrix` 和 TIDE，不另写一套指标匹配算法。诊断逻辑和界面分开，这样改按钮不会影响模型评估。

### 命令行仍然可用

```bash
mkdir -p data/runtime/Ultralytics
export YOLO_CONFIG_DIR="$PWD/data/runtime"
.venv/bin/python core/analyzer.py \
  --data /absolute/path/to/data.yaml \
  --model /absolute/path/to/problem.pt \
  --baseline /absolute/path/to/reference.pt \
  --imgsz 640 --conf 0.25 --device 0 \
  --output reports/my-new-run
```

省略 `--baseline` 就是单模型分析；输出目录必须是新目录。

## 7. 安装与支持范围

已在本机 Ubuntu、Python 3.10、PyTorch 2.12.0 上验证。当前版本使用 Linux 进程组实现取消，**尚未验证 Windows / macOS**。以后移植时，重点调整 `core/tasks.py` 的进程取消和启动脚本。

```bash
bash setup.sh
bash start.sh
```

安装脚本建立独立虚拟环境，允许复用本机已有的 PyTorch / CUDA，额外依赖安装在项目环境中。需要 Python 3.10+、pip，以及与显卡相符的 PyTorch。若新机器缺少这些基础组件，应先安装基础环境；脚本不会自动修改系统驱动。

网页只监听 `127.0.0.1`；文件选择和任务接口使用页面的随机令牌，不接受普通跨站请求。没有登录系统、云端上传或多人远程服务，不能直接当公网网站部署。

开源组件：Ultralytics（AGPL-3.0）、TIDE（MIT）。本项目从既有 Ultralytics 工作树中的诊断示例整理而来，保留 AGPL-3.0 许可文件。公开分发或继续开发时应遵守相应许可。

## 8. 当前边界

支持 YOLO 水平框目标检测；尚未接入分割、旋转框、姿态和分类任务。不会自动生成缺失标签、确认真实物品容量、判断遮挡程度、重训模型或保证找出唯一根因。没有完整训练数据版本和训练日志时，权重中的参数不足以还原训练过程。

## 第二版补充说明

`core/diagnosis.py` 是证据与建议规则的唯一入口，`core/ai.py` 管理 AI 请求，`ui/ai.js` 管理 AI 界面。两个模块不代替 `core/analyzer.py` 的原生指标算法。

补充参数也支持命令行：`--context /path/context.json --metadata /path/scenes.csv --train-run /path/run --baseline-run /path/old_run`。只填有对应资料的项；所选训练目录必须属于相应权重，这一对应关系不会因为路径存在就被程序认证。

DeepSeek 4.1 官方预设为 `https://api.deepseek.com/chat/completions` / `deepseek-flash`，模型名称依据 2026-09-15 核对的官方文档。API Key 只保留在服务内存。服务商模型映射会变化，后续应以其官方说明为准。

AI 功能不会主动访问你电脑里的其他文件，不提供自动执行命令、改标注或重训的工具。支持文字或最多 4 张报告 JPEG 预览图；发送内容以点击发送前的快照为准，不包含自动附加的浏览器历史。AI 成功结果保存在 `data/ai/<任务ID>/`，与检测报告分开。

### 验证范围

开发过程中已使用本地检测模型验证过推理、模型对照、取消任务和报告生成。仓库不附带这些私有数据，使用者应在自己的数据上复核。AI 接口已检查请求预览和错误处理，尚未完成真实 DeepSeek 付费接口的端到端验收。界面的模型系列选项不等于所有系列均经过测试；实际可加载范围受权重格式与固定版本 Ultralytics 限制。

### 关于“问题描述 JSON”和“逐图场景 CSV”

现在新建分析页面中的**问题描述**是普通文字输入框，不要求用户写 JSON。JSON 只保留给需要结构化记录现场配置、类别规则或部署参数的用户，完全可以留空。

**逐图场景 CSV** 不是 YOLO 标签，也不是必须的数据集文件。它只是给图片增加拍摄备注，例如这张图来自哪个批次、光线如何、是否遮挡、是否为你确认的现场失败图。没有这些备注时可以留空；模型仍然会使用图片和 YOLO 标签完成基本诊断。

新版问题图片区域按“人工标签 → 当前模型 → 对照模型 → 文字解释”排列；术语旁边直接说明 FN、FP、TP、IoU、TIDE 的含义。
